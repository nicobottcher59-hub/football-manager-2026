# Phase 5.7 — Match Flow

## Objective

Phase 5.7 connects the spatial systems implemented in Phases 5.0–5.6 into a complete match lifecycle.

The Match Engine can now progress autonomously through:

- kickoff;
- first half;
- added time;
- halftime;
- second half;
- extra time when required by the competition;
- penalty shootout when required;
- final result.

It also introduces basic dead-ball restarts and a structured event stream that later presentation layers can consume.

---

## Competition-derived match resolution

Match resolution is competition metadata, not a user-configurable pre-match option.

`CompetitionContextSnapshot.match_decider` supports:

```text
DRAW_ALLOWED
EXTRA_TIME_AND_PENALTIES
PENALTIES_AFTER_90
```

For cup ties, the current match score is combined with the frozen aggregate score from `CupTieContextSnapshot` before deciding whether the tie is level.

Examples:

```text
league match tied after 90 + added time
→ draw
```

```text
knockout tie level after 90 + added time
→ extra time
→ penalties if still level
```

```text
knockout tie already won on aggregate
→ no unnecessary extra time
```

---

## Period lifecycle

The default real match durations are:

```text
First half: 45 minutes + added time
Second half: 45 minutes + added time
Extra-time first half: 15 minutes + added time
Extra-time second half: 15 minutes + added time
```

The fixed Match Engine timestep remains `0.25 s`.

Phase/period boundaries do not create a second simulation path. The same spatial engine continues to advance through normal fixed ticks.

---

## Added time

The flow controller tracks effective stoppage time generated by events such as:

- goals;
- fouls;
- throw-ins;
- corners;
- goal kicks;
- free kicks.

At the nominal end of a period, accumulated stoppage time is converted into bounded added time.

The current weights/caps are an initial model and will be calibrated later.

The presentation clock is period-aware. Internal simulation time can remain continuous while display time can still show:

```text
45+2'
90+4'
105+1'
120+2'
```

rather than incorrectly carrying first-half added time into the second-half match clock.

## Autonomous action orchestration

`MatchFlowController` schedules the existing simulation systems instead of replacing them.

Conceptually:

```text
controlled ball owner
      ↓
DecisionSystem
      ↓
selected action
      ↓
existing executor
(pass / carry / dribble / cross / shot)
      ↓
fixed spatial ticks
      ↓
result
      ↓
score / possession / restart / next decision
```

The flow layer does not directly decide whether a pass succeeds, a dribble works or a shot becomes a goal.

Those outcomes remain owned by their Phase 5.3–5.6 execution systems.

---

## Defensive integration

During autonomous play, an active primary presser can attempt a defensive duel when physically close enough.

The existing Phase 5.4 tackle profile still determines:

- willingness to engage;
- duel probability;
- clean control;
- loose-ball outcomes.

A basic foul path is included so the match-flow layer can stop play and award a free kick.

Referee strictness, cards, penalties and richer foul logic remain Phase 5.8 work.

---

## Loose-ball recovery

A loose ball no longer leaves the autonomous match permanently stuck.

The flow layer waits a bounded amount of simulation time and then allows the nearest plausible player to recover it.

This is a first recovery model. More detailed anticipation, acceleration and contested loose-ball behaviour can be refined during calibration.

---

## Basic restarts

The first restart model supports:

```text
KICKOFF
THROW_IN
GOAL_KICK
CORNER
FREE_KICK
```

Restarts place the ball at a valid spatial location, select an appropriate restart taker and restore controlled possession.

Boundary logic can detect:

- touchline → throw-in to the opponent of the last touch;
- goal line + attacker last touch → goal kick;
- goal line + defender last touch → corner.

Shot outcomes are also connected to flow:

```text
GOAL
→ score update
→ kickoff to conceding team

OFF_TARGET
→ goal kick

SAVED
→ goalkeeper possession continues

PARRIED / BLOCKED / WOODWORK
→ live loose-ball state continues
```

---

## Score and aggregate score

`MatchScore` stores the current match score and, when needed, penalty-shootout score.

`MatchResult` exposes:

- home goals;
- away goals;
- aggregate home goals;
- aggregate away goals;
- winner;
- end reason;
- penalty score;
- structured events.

Possible end reasons are:

```text
DRAW
REGULATION
EXTRA_TIME
PENALTIES
```

---

## Penalty shootout

When the competition requires a winner and the tie remains level, a deterministic penalty shootout is run.

Penalty takers are selected from active outfield players using penalty-taking and composure as ordering inputs.

Conversion probability is separated from goalkeeper resistance and uses the same match-owned seeded random source.

The shootout supports:

- five scheduled rounds;
- early mathematical completion;
- sudden death;
- deterministic replay from the same snapshot/seed.

This shootout model is intentionally compact. Normal in-match penalties and richer goalkeeper/penalty behaviour can be refined later.

## Structured Event Stream

Phase 5.7 introduces match-flow events with:

- sequence number;
- simulation tick;
- football time label;
- match phase;
- event type;
- team side;
- actor/secondary player IDs;
- restart type when relevant;
- structured metadata.

Examples include:

```text
PASS
CARRY
DRIBBLE
CROSS
SHOT
GOAL
SAVE
BLOCK
WOODWORK
RECOVERY
TACKLE
FOUL
RESTART
ADDED_TIME
MATCH_END
```

This is the foundation for Phase 5.9 text commentary and the 2D/debug frontend.

A presentation layer can choose which events to expose; it does not need to display every raw event.

---

## Determinism

The match flow uses the same match-owned RNG already created by `SpatialMatchEngine`.

Therefore:

```text
same MatchSnapshot
+ same seed
+ same engine version
+ same FlowConfig
= same autonomous match flow
```

No separate randomness source is introduced for match orchestration or shootouts.

---

## Current calibration status

Phase 5.7 proves that the systems can be orchestrated into a match that starts, progresses and finishes without manual debug calls.

It does **not** claim that current full-match statistical distributions are calibrated.

For example, current frequencies of:

- passes;
- shots;
- goals;
- crosses;
- tackles;
- fouls;
- added time;

are still provisional.

Large-scale realism and distribution tuning belongs to Phase 5.10.
